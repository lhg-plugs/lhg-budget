# lhg-budget-categorize：自动分类四步法

> **合规声明**：本方法论仅用于记账与预算分析，**不构成任何投资建议**；涉及投资决策请咨询持牌专业人士。

## 1. 何时使用 / 何时不用

**用**：统一账本已导入（`ledger-YYYYMM.csv`），`分类` 列大量空白，需要把每笔支出归入"餐饮/交通/居住/…"等分类，才能出占比报表。

**不用**：
- 账单自带分类列且覆盖率 ≥ 90% → 直接用，不必重跑。
- 用户只想看"总共花了多少" → 分类是可选成本，先出总数。
- 覆盖率目标达不到 70% 且用户不愿补规则 → 停下出"未分类"报表，不许硬猜分类凑数。

## 2. 输入与输出

**输入**：`ledger-YYYYMM.csv`（分类列可空）。

**输出**：同一文件，`分类` 列填上"一级·二级"（如 `餐饮·外卖`），外加一份 `category-map.json`（商家学习表，见第 3 步）。

**分类树**（五级为上限，小白记账够用，太细坚持不下去）：

```
收入
├── 收入·工资薪金
├── 收入·经营所得
├── 收入·转账红包
└── 收入·其他
支出
├── 餐饮（外卖/堂食/咖啡奶茶/买菜）
├── 交通（打车/地铁公交/加油/停车）
├── 居住（房租/水电燃气/物业/话费网费）
├── 消费（购物/美妆/数码/服饰）
├── 医疗（挂号/买药/体检）
├── 教育（课程/书籍/考试）
├── 社交（请客/礼金/娱乐）
├── 金融（手续费/还款利息）
└── 其他（实在分不出的）
```

原则：**宁可进"其他"，不许进错类**。错分类比未分类更伤害报表可信度。

## 3. 分步方法论

### 第 1 步：关键词规则库（先行，零学习成本）

按"对方/商品/备注"字段做包含匹配，优先级：**精确商家名 > 品类词 > 通用词**。

示例规则（节选，完整库见仓库 `references/` 或按此格式自建）：

| 匹配词 | 分类 | 说明 |
|---|---|---|
| 瑞幸/星巴克/库迪/Manner | 餐饮·咖啡奶茶 | 精确商家 |
| 美团外卖/饿了么 | 餐饮·外卖 | 平台词 |
| 滴滴/高德打车/T3 | 交通·打车 | 精确商家 |
| 12306/携程 | 交通·差旅 | 精确商家 |
| 房东/自如/贝壳 | 居住·房租 | 场景词 |
| 国家电网/水务/燃气 | 居住·水电燃气 | 机构词 |
| 京东/淘宝/拼多多 | 消费·购物 | 平台词（备注有"买菜"→餐饮·买菜，覆盖） |
| 医院/药房/叮当快药 | 医疗 | 场景词 |
| 工资/奖金 | 收入·工资薪金 | 收入侧 |

冲突解决：一条交易命中多条规则 → 取**最长匹配词**的那条；仍冲突 → 进待确认队列，不抛硬币。

### 第 2 步：商家学习表（越用越准）

文件 `category-map.json`，格式：

```json
{
  "星巴克臻选上海静安店": "餐饮·咖啡奶茶",
  "小区门口沙县小吃": "餐饮·堂食"
}
```

- 用户在第 3 步确认过的商家 → 写入，下次同名直接命中（精确匹配优先于关键词）。
- 学习表按"命中次数"排序展示，方便用户定期清理改名的商家。

### 第 3 步：待确认队列（一次问完，不骚扰）

规则库 + 学习表都 miss 的交易 → 收拢成队列，**按对方聚合**（同一商家多笔只问一次），每家给 3 个候选分类：

```
以下 6 个商家没见过，帮你猜了最可能的 3 个，选一个（或自定义）：
1. "杨国福麻辣烫（五角场店）" → A 餐饮·堂食 / B 餐饮·外卖 / C 其他
2. "上海图书馆" → A 教育·书籍 / B 社交·娱乐 / C 其他
...
```

用户选完 → 写回学习表。**不许在没问的情况下把猜测直接当结论落盘**。

### 第 4 步：覆盖率门禁

- 覆盖率 = 已分类笔数 / 总支出笔数（收入侧不计）。
- ≥ 90%：通过，直接出报表。
- 70%~90%：出报表，但"其他/未分类"单独成行展示，不许并入其他分类。
- < 70%：**停下**，告诉用户缺口在哪几类商家，问他要不要补规则或放宽到"先出未分类版报表"。硬凑分类 = 编造数据。

## 4. 反模式（不要这样做）

- ❌ 用"看起来像"硬分类（如"XX 商贸"→消费·购物，可能是公司报销）→ 进待确认。
- ❌ 分类粒度一上来就定 30 个二级 → 小白三天就放弃。先 9 个一级跑顺再细化。
- ❌ 把退款/冲销单独记支出 → 退款应冲减原分类支出（备注标"退款"），否则支出虚高。
- ❌ 转账（自己转自己，如银行卡→支付宝）记成支出 → 应标记"内部转账"，不计入收支统计。
- ❌ 学习表无脑追加不清理 → 商家改名后旧映射污染新数据，每季度清一次。

## 5. 自检与反馈

**质检门**：
1. 抽查 10 笔已分类交易，商家与分类是否对得上（错 1 笔即回查规则）？
2. "其他"占比是否 < 15%（超过说明规则库太薄）？
3. 有无把猜测当结论落盘的（查待确认队列是否清空）？
4. 退款/内部转账是否正确处理（未计入支出）？

**标准冒烟用例**：`fixtures/csv-good/` 的账本分类覆盖率应 ≥ 90% 且零 blocker；`fixtures/csv-bad/` 应触发 B-CAT-001（未分类率过高）。

**一键反馈**：某类商家长期 miss（如你们小区的菜市场）→ 提 issue（标题：`[categorize] 新增关键词：<商家词> → <分类>`），维护者会并入规则库。

## 附：特殊交易处理手册

### 退款 / 冲销
- 账单里"退款"行（金额为正、对方与某笔支出相同）→ 找到原支出笔，备注标"已退款 ¥X"，**分类统计时从原分类中扣减**，而不是记一笔"收入"。
- 找不到原支出笔 → 记 `收入·退款`，备注写清对方和日期，待用户确认。

### 内部转账（自己转自己）
- 银行卡→支付宝/微信、支付宝→银行卡、信用卡还款：记分类 `转账·内部`，**不计入收入/支出总额**。
- 识别信号：对方是自己的名字/尾号、备注含"转账""还款""充值"。

### 报销 / 代付
- 帮同事代付、公司报销：记 `其他·代付`，并在备注写"待报销"；报销到账后冲销。
- 不要把"待报销"混进日常消费，否则这个月支出虚高，下个月收入虚高。

### 信用卡账单
- 信用卡账单是"负债账单"不是"消费账单"：优先用支付宝/微信的消费明细做分类，信用卡只用来核对总额。
- 还款 = 内部转账，不记支出。

## 附：规则库扩展示例（按场景加词）

| 场景 | 加词 | 分类 |
|---|---|---|
| 早餐摊 | 沙县/兰州拉面/包子铺 | 餐饮·堂食 |
| 买菜 | 盒马/叮咚/菜市场 | 餐饮·买菜 |
| 通勤 | 地铁/公交/哈啰单车 | 交通·公共交通 |
| 停车 | 停车费/ETC | 交通·停车 |
| 话费网费 | 移动/联通/电信/宽带 | 居住·话费网费 |
| 订阅 | 爱奇艺/腾讯视频/网易云/iCloud | 消费·订阅 |
| 宠物 | 宠物医院/狗粮 | 消费·宠物 |
| 人情 | 份子钱/红包（支出侧） | 社交·礼金 |

加词原则：先加**自己常去**的 20 个商家，覆盖 80% 笔数；冷门商家走待确认队列，不要一次性加 500 个词。
